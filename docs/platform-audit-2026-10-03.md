# Platform audit — 3 October 2026

Scope: source review of admin authentication, permissions, CRM intake and conversion, invoice/payment queries and actions, financial summaries, uploads, CMS publishing, public submission routes, schema and workspace tooling. Existing Graphify graph used for navigation; findings verified against current source. No production data accessed, no application code changed. `pnpm type-check` passed for both apps. No database integration tests, browser checks, query plans, backup inspection or load tests performed. Risks below are code-supported; actual historical data loss or unauthorized access is not established.

Extend these flows instead of building another CRM alongside them.

## Bottlenecks and operations

- Lists load all invoices, contacts, payments and related records. Finance page reloads invoices and expenses already fetched inside its summary. Use server pagination/filtering and database aggregates; fetch detail relations only for detail pages.
- Payment lists repeatedly include each invoice's complete payment and line-item collections. Select the displayed fields and aggregate balances once. These are observed query shapes, not measured latency findings.
- Add indexes based on actual query plans: candidates include invoice status/dueDate, calendar startDate, attachment entityType/entityId and invoice-line invoiceId. Existing indexes already cover several CRM foreign keys and identity lookups. Ordinary indexes will not automatically fix contains/ILIKE search; evaluate PostgreSQL trigram search only when measurements justify it.
- Uploaded files live in public local directories, including payment evidence, vault and certificates. Use private durable storage and authorized downloads for confidential files; public media can use public delivery. Local files may be lost or unavailable across deployment instances, depending on hosting.
- CMS invalidation often targets nonlocalized paths while actual routes use /en and /ar; data queries have no observed unstable_cache tags. Verify caching behavior before selecting one consistent tag/path strategy. Revalidation helper ignores HTTP error status and silently returns without configuration, so publishing can falsely appear complete.
- Public inquiry/review routes and login lack observed application-level rate limiting. Add runtime type/length validation and abuse protection; external edge protection was not inspected. Email delivery errors are returned by sendEmail but ignored by inquiry submission. Record delivery state and retry without duplicating the lead; reject mock success in production when email is required.
- No versioned Prisma migration files or application test files found in the reviewed tree. Use reviewed migrations for production schema changes and add targeted checks for permissions, conversion, rollback, number allocation and payment reconciliation. Verify backups with a restore drill before relying on them; deployment backups are unknown.

## Feature roadmap

1. Reliability: close access gaps, patch dependencies, protect private files, fix invoice transactions and payment validation, normalize identity, repair conversion and error reporting.
2. Sales workflow: owners, next action/due date, overdue follow-up queue, lost reason and stage history, duplicate/conflict resolution, CSV import preview/export, and source/UTM tracking. Reuse existing deal assignedTo/lostReason and calendar models where practical; explicit links and permissions remain necessary.
3. Commercial workflow: quotes with revisions and accept/reject tracking, convert accepted quote to deal/invoice, milestone billing, reminders, refunds/credit adjustments and project profitability. Contract/template models exist, but no complete contract management routes/actions were found; a schema model is not a shipped workflow.
4. Website management: draft/preview/publish and revision restore, scheduled banners/portfolio, bilingual completion checks, SEO titles/descriptions/social images, sitemap/robots and redirects, media library with alt text and private/public separation. Public services currently come from locale content rather than the admin service catalogue; explicitly decide whether to unify the catalogue and marketing content.
5. Production workflow, when needed: crew/equipment availability, booking conflict checks, shoot milestones and deliverable approval. Avoid inventory procurement, a generic workflow builder or full ticketing until real usage establishes the need.

Acceptance checks: unauthorized users cannot read/mutate/export restricted resources; revoked tokens fail; failed edits preserve invoice items; simultaneous creation gets distinct numbers; lead conversion creates exactly one deal; invalid or void payments fail; metrics respect currency and state; publishing updates both locales; lost emails can be retried safely; restored backup reproduces known records and private files.
